trust, then check

Check what you downloaded. It takes a minute.

Your device checks everything in hoi: every post, every vote, every moderator action. The one thing it can't check is itself. The app you run is the trust boundary, so here is how to make sure it's the one we signed, and not something that looks like it.

1Find the checksum

Every file in a release has a SHA-256 checksum in the release list, manifest.json. The download page shows it next to each file, with a copy button.

2Hash your file

Run the line for your system on the file you downloaded. Your file name may differ a little.

macOS · Terminal
shasum -a 256 ~/Downloads/hoi_0.1.0_universal.dmg
Linux · any shell
sha256sum hoi_0.1.0_amd64.AppImage
Windows · Command Prompt
certutil -hashfile hoi_0.1.0_x64_en-US.msi SHA256
Windows · PowerShell
Get-FileHash .\hoi_0.1.0_x64_en-US.msi -Algorithm SHA256

The output must match the checksum, character for character. Upper or lower case doesn't matter. If it doesn't match, delete the file and don't open it. A broken download and a swapped one look the same from here.

3Check the list is ours

A matching checksum proves the file matches the list. The signature proves the list came from the publisher of the trusted key. Download manifest.json and manifest.json.minisig into one folder, then run minisign with the key below:

Any system with minisign
minisign -Vm manifest.json -P '{{RELEASE_KEY}}'

It should say Signature and comment signature verified. Anything else: stop, and tell us.

Build's trusted release key

hoi release signing key (minisign)

{{RELEASE_KEY}}

Compare this key with publication.json in a source checkout you already trust. A key supplied only by the downloaded list is not trusted. If the keys disagree, stop.

The download page and app verify the exact signed list before using its URLs or notices. Desktop updates also verify the selected package's checksum, updater signature and version. These checks are separate from operating-system code signing or notarisation. Browser app updates use the browser's HTTPS and service-worker cache; a signed notice does not authenticate every file served by the website.

4Or build it yourself

Don't want to trust our build at all? Fair. Check out the release tag and build from source. You need Node 22 or newer, pnpm 10 and stable Rust; the desktop app also needs Tauri's prerequisites.

Build from source
git clone {{REPO_URL}}.git
cd hoi
git checkout v0.1.0
pnpm install --frozen-lockfile
node scripts/reproduce.mjs
pnpm --filter @hoi/desktop tauri build

Then compare what you built with what we published. The browser app's WebAssembly, hoi-node and this website come out byte for byte the same on any machine with the pinned toolchains: node scripts/reproduce.mjs builds them and prints their SHA-256, and each hoi-node download has its digests beside it. Our checks build everything twice and fail on a single byte. The desktop installers don't: signing and packaging add timestamps and certificates on each build. Their programs come from the same sources, built the same way.

why bother

The app is the bouncer. Check the bouncer.

Your copy of the app checks signatures, stamps and rate limits on the records it receives. A compromised app could skip those checks or leak your keys, including private-message keys. Verify the download against a trusted publisher's signing key; encryption still depends on the client you run.

What we sign, and what we don't

Release downloads have checksums and a signed release list. The app can fetch static release metadata; it includes no analytics or crash reporting. Community discovery and synchronization contact separate nodes directly, as described in the privacy notice.
