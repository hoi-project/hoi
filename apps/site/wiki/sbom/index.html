Software bill of materials

Everything hoi is built from: every Rust crate, npm package, vendored patch, toolchain, container image and CI action, with the exact version, its license, the program that uses it and how. Built from the lockfiles every time the site is built, so it can't drift from the code.

Reading it

runtimemint tag

Compiled or bundled into the program you run: the node binary, the WebAssembly core, the app bundle, the desktop executable.

build timesky tag

Runs only while compiling: build scripts and procedural macros. It shapes the binary but isn't in it.

developmentgrey tag

Bundlers, type checkers, test runners and fuzzers. Never shipped.

★direct

The program's own manifest names it. Everything else arrives through another package.

platform listafter a tag

Present only when building for those platforms, for example a Windows-only system crate in the desktop app.

first-partybadge

hoi's own crates, which the desktop and setup workspaces use by path.

vendoredbadge

A published package kept in vendor/ with a small reviewed patch; the build uses that copy instead of the registry's. See Supply chain & hardening.

What this doesn't list

The operating system and browser you run hoi on, and the system libraries the desktop apps link against there (WebKitGTK on Linux, WebView2 on Windows, WebKit on macOS). Those come with your system, not with hoi.
