Crates in core/

The Rust workspace in core/ holds fourteen crates. Eight small ones each do one job without I/O (records, crypto, validation, storage, moderation, trust, spam, sync), hoi-core puts them behind one Node, and five more carry that node to sockets, browsers, phones, servers and the simulator. This page goes through every crate: its files, its public items, its Cargo features, what it pulls in and what pulls it in.

Source core/Cargo.toml · core/README.md · core/crates/ · core/fuzz/Cargo.toml · core/rust-toolchain.toml

The workspace

core/Cargo.toml declares resolver = "3" and members = ["crates/*"], so every directory under core/crates/ is a member. Every crate inherits its package metadata from [workspace.package]:

version1.0.0-preview.1
One version for the whole workspace. hoi_core::VERSION is env!("CARGO_PKG_VERSION"), so boot() reports it.
edition2024
Rust 2024 edition everywhere (the fuzz crate says so on its own too).
rust-version1.94
The minimum Rust the manifests accept. The vendored OpenMLS provider migration raised it to 1.94.
licenseAGPL-3.0-only
Every crate.
publishfalse
Nothing goes to crates.io; hoi-ffi repeats publish = false in its own manifest.

Toolchain and formatting

[toolchain]
channel = "1.97.0"
components = ["rustfmt", "clippy"]
targets = ["wasm32-unknown-unknown"]

So a checkout builds with Rust 1.97.0 exactly, with the browser target installed. core/rustfmt.toml sets max_width = 160 and use_small_heuristics = "Max": lines run long, and short expressions stay on one line. Building and testing are on Building & testing.

Because the wasm profile aborts on panic, a decoder bug inside the worker would take the whole node down. That is why the browser core sets set_look_elsewhere(true) and decodes pictures in a separate look worker (see hoi-wasm).

Workspaces next to this one

  • core/fuzz is a workspace of its own ([workspace] members = ["."]), so libfuzzer-sys stays out of core/Cargo.lock. It needs nightly. See Fuzz targets.

hoi-moderation

A community's state as a pure function of its genesis, its ledger entries and the community's own vouches and reviews. Entries are replayed in (at, seq, id) order, each checked against the state before it; the ladder then settles who stands where, and overturned entries, suspended moderators and accepted proposals feed back until nothing changes. Replaying from scratch makes the result independent of arrival order. See Communities & the ledger and Standing & review.

hoi-core

The one crate that does all the thinking. It owns a Node: the store, every community's state, local state and keys. Every record goes through the pipeline, its effects are applied, changes are persisted and gossip is queued. UIs call it directly, through Node::call JSON dispatch, through hoi-wasm or through hoi-ffi; they never touch keys, storage or the network themselves. The API is documented on Core API.

hoi-net

Moving sync messages between nodes. The node decides what to say; this crate owns sockets. Shared keeps one Node behind a mutex with an outbox router and an event callback, and every host goes through Shared::with, which runs a closure, commits, routes queued messages and reports events. The transports themselves are on Transports.

hoi-wasm

The core for browsers. The web app runs WasmNode in a dedicated Web Worker; storage and sockets stay in JavaScript, which drains take_changes and take_outbox after every call. A pool of mining workers calls mine_range, and a separate look worker fingerprints media. Its exports are listed on Core API; the app around it on Web app.

hoi-ffi

hoi-core for the native phone apps through UniFFI. HoiNode is one object per app process: it opens SQLite at <data_dir>/hoi.db, keeps a small tokio runtime for the home-node link and the sweeper, and exposes the whole HoiCore API as typed methods. Fuzz targets

core/fuzz (hoi-fuzz) holds ten libfuzzer-sys 0.4 targets for the decoders: anything that takes bytes or text from strangers. It depends on hoi-types, hoi-crypto, hoi-validate, hoi-sync and loro =1.17.1 by path, needs nightly, and runs from core/fuzz:

cargo +nightly fuzz list            # the ten targets
cargo +nightly fuzz run manifest    # fuzz one
