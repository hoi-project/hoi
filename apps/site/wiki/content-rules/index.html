Text, links & names

The rules every piece of text people read must pass: titles, posts, comments, names, labels and reasons. They refuse characters with a history of abuse (direction tricks, invisible and smuggled text), raw HTML and embedded media, links that hide where they lead, and copy-paste floods. A record either passes them or is refused, on the device that writes it and on every device that receives it.

Pass or refuse, never clean

Records are signed and immutable: changing one byte changes its id and breaks its signature. So nothing is cleaned up on arrival. There is no stripping, no rewriting, and no Unicode normalization (NFC, NFKC or confusable folding) anywhere in the checks: the text a person signed is the text everyone stores, or nobody does.

The same functions run in two places. The app calls hoi_validate::content while preparing a post, reply or edit, so a person hears what's wrong before anything is stamped. Every receiving device calls it again at the content stage of the validation pipeline. A refusal there is Reject::Content(message); when the record came from a peer, its author's key takes a strike of weight 3 (Spam & rate limits).

Body::Post { title, text: t, link, name: n, media } => {
    c(text::line(title, "title", 300, true))?;
    c(text::markdown(t, "text", 40_000, 2000))?;
    if let Some(l) = link {
        c(text::url(l).map_err(|e| format!("link: {e}")))?;
    }
    media_refs(media)?;
    name(n)
}

Why tags, selectors and joiners

Tag characters (U+E0020–U+E007E) and the supplementary variation selectors render as nothing, so runs of them can spell out text nobody sees: hidden from readers, and not hidden from language models asked to summarize the thread. The rules refuse the runs and keep the ordinary uses: tags inside a flag, one selector after a character, one joiner between two.

What still works

  • Every script, either direction. Hebrew, Arabic, Persian with its ZWNJ (می‌خواهم), Hangul, Devanagari: only the characters in the table are refused.
  • Emoji sequences. A single VS16 (❤️), ZWJ sequences (👩‍💻), skin tones.
  • Subdivision flags. After U+1F3F4 WAVING BLACK FLAG, up to eight tag characters are allowed, and U+E007F CANCEL TAG ends the sequence once at least one tag came (🏴󠁧󠁢󠁳󠁣󠁴󠁿, Scotland). Any other character ends it too.
  • Accents. Up to four combining marks in a row (é\u{0301} passes).
match c {

Body text: the markdown subset

Post, comment, edit and rules text goes through text::markdown(s, what, max_chars, max_lines). It doesn't parse a markdown grammar; it refuses the constructs a renderer could turn into something other than text, in this order:

  1. Length

    More than max_chars characters (Unicode scalar values): "is too long". More than max_lines newline characters: "has too many lines".

  2. Characters

    Every character through chars(s, Field::Body, …), the table above.

  3. No raw HTML

    A < followed by an ASCII letter, /, ! or ? anywhere: "contains raw HTML". That catches tags, closing tags, comments, doctypes and processing instructions, and leaves comparisons alone: 2 < 3 and 5 > 4 passes.

  4. No embedded media

    The two characters ![ anywhere: "embeds media". Pictures travel as media items, checked byte by byte (Media), never as a link a renderer would fetch.

  5. At most eight addresses

    Every http:// or https:// in the text, in any letter case, counts as a bare address, as renderers would auto-link it: it runs to the next whitespace or one of ) > " ' < ], without trailing . , ; : ! ?. More than MAX_LINKS (8): "has more than 8 links". Each must pass the address rules.

  6. Link targets

    Every inline link [text](target) and every reference definition [ref]: target (a line starting with [ after at most three spaces) has its target checked, with surrounding < > trimmed. Empty targets and in-page anchors starting with # are skipped. Any other target must be an address that passes the rules ("text: link address must start with http:// or https://" for javascript:, JAVASCRIPT: and data: alike), and the link text must not name a different site (below).

IPv4 hosts are recognized only in dotted-decimal form. The other spellings browsers accept for 127.0.0.1 (one decimal number, hex labels) fail rule 13: a top-level label is never all digits and never starts with 0x.

Look-alike hosts

  • A username before the host. https://paypal.com@evil.example/ goes to evil.example. Any @ in the authority is refused.
  • International names in the clear. A non-ASCII host could mix scripts so аpple.com (with a Cyrillic а) reads as apple.com. Hosts must be ASCII; a real international name is written in punycode, xn--…, where the difference shows.
  • Backslashes. Some parsers read \ as / and some don't, so where the host ends depends on who reads it. Refused in the authority.
  • Unusual names. Only letters, digits, hyphens and dots; labels of 1–63 characters, no hyphen at either end, at most 253 characters in all.

Handles that are domains follow their own, similar rule (below).

Link text that names another site

[paypal.com](https://evil.example/login) shows one site and goes to another. For every inline link whose text reads like a site name, the text's site and the target's host must be the same site, or one a subdomain of the other.

/// Whether link text reads like a site name of its own ("paypal.com", "https://x.y/z").
fn looks_like_site(text: &str) -> Option<String> {
    let t = text.trim();
    if t.len() < 4 || t.contains(char::is_whitespace) || !t.contains('.') {
        return None;
    }
    let with_scheme =
        if t.to_ascii_lowercase().starts_with("http://") || t.to_ascii_lowercase().starts_with("https://") { t.to_string() } else { format!("https://{t}") };
    let h = host_of(&with_scheme)?;
    let tld = h.rsplit('.').next()?;
    (tld.len() >= 2 && tld.bytes().all(|b| b.is_ascii_alphabetic())).then_some(h)
}

fn same_site(a: &str, b: &str) -> bool {
    a == b || a.ends_with(&format!(".{b}")) || b.ends_with(&format!(".{a}"))
}

host_of lowercases the host, drops trailing dots and a leading www.. Link text with a space in it, or without a dot, or with a numeric or one-letter ending, is just text. The link's text is what lies between the last [ on the same line and the ](.

Links and newcomers

Newcomers share text only. hoi_validate::has_links says whether a post, comment or edit carries anything a renderer would follow: a link, or text (or a title) containing http://, https:// or www. in any case, or any link target that isn't empty and isn't a # anchor.

A record with links from someone below member standing in that community is not refused: it is stored and held, shown to nobody but its author and passed on to nobody, with the reason "links unlock once the community has vouched for you". The app refuses it up front ("Newcomers share text only. Links unlock once members here vouch for you."). Owners and moderators are never held. See Standing & review.

Display names

Anyone can claim any name, so a name is never an identity: it rides on posts and comments (their optional name field) and devices show it next to the key. text::name keeps names from dressing up as something else:

The short form of a key is written a7f2·91c0 (the first eight hex digits, split by a middle dot), and full keys are did:key:z6Mk…; names may look like neither. Ana María and lena pass.

Where a person types a name (their own, a petname for someone else, a label for one of their devices, the label of a device link request), the app runs clean_name first: whitespace runs collapse to one space and the ends are trimmed, then text::name applies, and the error reads "That name won't do: …". The name a device shows for a person is the petname this person gave them, else the newest name they used in a post or comment, else their short key (Keys & identity).

Other names and reasons

Community names

A community's name in its genesis is a line of 1–40 characters; its description at most 300 characters of body text; its color one of mint, sky, lilac, peach, sun, coral. A name registered with a registry is stricter: community_registration_name trims and lowercases it, then requires 1–32 characters, the first a letter or digit, all of a–z, 0–9, ., _, - (Registry).

Handles: names that are domains

A display name that is a domain gets checked against the domain (Keys & identity). handle::as_domain decides whether a name is one: trimmed, trailing dots dropped, lowercased; at most 253 characters with at least one dot; two labels or more, each 1–63 of a–z, 0–9 and -, no hyphen at either end; a top-level label of at least two characters, all letters or starting with xn--.

Copy-paste floods

The same words posted again and again are refused by fingerprint. text_fingerprint takes a post's title, text and link joined by newlines, or a comment's text, lowercases it, collapses every run of whitespace to one space, and keeps the first 16 bytes of its BLAKE3 hash. Texts under 12 characters after that have no fingerprint ("too short to mean anything"); edits and other kinds have none.

pub fn text_fingerprint(r: &Record) -> Option<[u8; 16]> {
    let words = match &r.body {
        Body::Post { title, text: t, link, .. } => format!("{title}\n{t}\n{}", link.as_deref().unwrap_or("")),
        Body::Comment { text: t, .. } => t.clone(),
        _ => return None,
    };
    let norm: String = words.to_lowercase().split_whitespace().collect::<Vec<_>>().join(" ");
    if norm.chars().count() < 12 {
        return None;
    }
    let h = blake3::hash(norm.as_bytes());
    Some(h.as_bytes()[..16].try_into().expect("16"))
}

So a post titled Free crypto saying click here now and one titled free CRYPTO saying click here, a newline, now have the same fingerprint. The store indexes every post and comment by (community, fingerprint), and check_duplicate in node.rs refuses, as Content:

WhenMessage
The same person already used these words in this community within 7 days of this record's created_atthe same words again
The author is a newcomer, and two or more other newcomers used these words within a daythe same words from several newcomers: a copy-paste flood

A flood from a peer costs the key a strike of weight 0.25 (Offence::Duplicate); a device that reports it gives the reason dup. The check is skipped for records read back from disk. Picture copies are caught differently, by perceptual hash (Media).

Where the rules are tested

The examples on this page come from the unit tests in text.rs (smuggling_is_refused, names, addresses, markdown_links) and lib.rs (content_rules, new_kinds_content, fingerprints_ignore_case_and_spacing), plus domains_are_names_that_look_like_one in handle.rs. A property test feeds markdown, name, url and has_links arbitrary strings of up to 200 characters and requires that none of them panics.
